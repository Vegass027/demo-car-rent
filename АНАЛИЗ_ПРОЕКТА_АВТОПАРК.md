# ПРОЕКТ: Автопарк CRM (car-rent)

## 📋 Общая информация
- **Название:** Автопарк CRM
- **Краткое описание (1-2 предложения, что делает):** CRM-система для управления автопарком (каршерингом/арендой): учёт машин, записей аренды, клиентов, расходов, зарплат, финансов и договоров выкупа. Работает как PWA с поддержкой Telegram WebApp и кастомной JWT-авторизацией через Supabase Edge Functions.
- **Тип:** веб-приложение (PWA + Telegram Mini App)
- **Стадия:** работающий продакшн / MVP в активной разработке (есть `dist/`, `dev-dist/`, продакшен-сборки от 30 мая 2026; есть план доработок `plans/buyout-improvements.md` со статусом «На согласовании»)
- **Соло или команда:** соло
- **Назначение:** для бизнеса (реальный владелец автопарка; в коде встречается `username: 'owner'`, фигурирует «Владелец», есть логика зарплат и комиссий менеджера)

## 🛠️ Технологический стек
- **Язык(и):** TypeScript (strict), SQL (Postgres), немного Python (`extract_docx.py`)
- **Основные фреймворки:**
  - Frontend: React 19 + Vite 7 + React Router 7 + TanStack Query 5 + Zustand 5
  - UI: TailwindCSS 4 + Radix UI + retro-UI компоненты (retroui) + lucide-react + framer-motion + recharts + sonner (toast)
  - Forms: React Hook Form + Zod
  - PWA: `vite-plugin-pwa` + Workbox + Telegram WebApp SDK
- **База данных:** Supabase (PostgreSQL 15+), кастомная схема с RLS, триггерами и RPC; 22 файла миграций в `database/` и `supabase/migrations/`
- **AI/LLM инструменты в продукте:** нет (продукт сам не использует AI/LLM — обычная CRUD/аналитика CRM)
- **AI-инструменты при разработке:** **Kilo Code IDE** (текущая среда — `.kilo/` + `.kilocode/rules/`), MCP-серверы (context7, supabase-cloud, supabase-self-hosted) настроены в `.kilocode/mcp.json`. В корне лежат большие файлы-инструкции для агента: `ИНСТРУКЦИЯ_ДЛЯ_АГЕНТА.md`, `car-rent.md` (визуальная концепция), `analytics.md`, `dump-base-instruction.md`, `plans/buyout-improvements.md`. Папка `.kilocode/rules/` содержит 6 детальных правил (Car-Rent.md, REACT_RULEZ.md, Global_rules.md и др.) — это всё признаки AI-first / vibe-coding разработки.
- **Хостинг / деплой:** Vercel (`vercel.json` с rewrite на `/`); backend — Supabase Cloud
- **Прочее:** Deno-совместимые Supabase Edge Functions (`supabase/functions/login`, `supabase/functions/change-password`); кастомная JWT-авторизация вместо Supabase Auth; ESLint 9 + typescript-eslint; в `vite.config.ts` настроена PWA с runtime caching (NetworkOnly для Supabase, CacheFirst для изображений).

## ✨ Ключевые функции (3-7 пунктов)
1. **Дашборд (Пульт):** месячная сводка (выручка / расходы / прибыль / касса), графики динамики прибыли (AreaChart), структура расходов по категориям (PieChart), загрузка автопарка (BarChart), фильтры по периоду и машине.
2. **Управление автопарком:** CRUD машин со статусами (`rented | free | service | inactive | buyout | bought`), фото, цветными метками, ТО-трекинг, расчёт ROI и окупаемости, страница детальной аналитики по каждой машине (`CarDetail.tsx`, 1697 строк).
3. **Журнал записей (`Journal`):** ежедневные записи аренды/расходов с типами (`normal | booking | buyout | buyout_payment | service`), категории расходов, генерация `.docx` договоров аренды и выкупа (`contractGenerator.ts`, 167 KB).
4. **Финансы (`Finance`):** большая страница (3504 строки) с cash-flow, расчётом зарплат менеджера, выводом средств, комиссиями, выкупными платежами.
5. **Клиенты:** база клиентов с поиском, документами (СТС, вод. удостоверение, родственники), историей договоров.
6. **Кастомная авторизация:** логин/пароль через Edge Function `login` с JWT, смена пароля через `change-password`, RLS-политики на основе helper-функций `is_owner()` / `is_manager()`.
7. **PWA + Telegram Mini App:** `vite-plugin-pwa` с Service Worker, manifest, offline-страница (`Offline.tsx`), Telegram WebApp SDK подключён в `index.html`, адаптивная вёрстка под portrait-режим.

## 💡 Что делает проект интересным (твоя оценка для портфолио)
Это реальный бизнесовый CRM, а не игрушечный todo-list: в нём замкнутая предметная область с нетривиальной логикой (договоры выкупа с процентом прибыли, комиссии менеджера, cash-flow, типы записей `normal/booking/buyout/buyout_payment/service`, генерация `.docx` договоров). Архитектура чистая: API-слой отдельно от UI, TanStack Query для серверного стейта, Zustand только для UI, RLS + кастомные Edge Functions вместо стандартного Supabase Auth — это показывает зрелость решений. Проект работает одновременно как PWA и Telegram Mini App, что редкость. Самое главное — он **полностью AI-first по процессу разработки**: видна целая «экосистема» из MCP-серверов, LLM-правил, markdown-инструкций и планов — это редкий и наглядный кейс для позиционирования как vibe coder.
